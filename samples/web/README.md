# JchuComponents web catalog

A Compose Multiplatform (Kotlin/Wasm) app that runs the real library in the browser: components, extensions and
date helpers, each with live controls and the code to use it. It is the home page of the GitHub Pages site, published by
`.github/workflows/docs.yml`; the Dokka API reference lives under `/api/`.

The two are complementary: the catalog shows how to use the most common composables, extensions and utilities of `ui`
and `foundation`, while Dokka documents every public symbol of all modules. Each demo has an **API reference** button
that opens the exact Dokka page; the links come from `ApiLinks.kt`, generated by `:samples:web:generateApiLinks` from the
sources, so they cannot go stale. When running locally there is no `/api/`, so those buttons only work on the published site.
Old links to the Dokka root are redirected to `/api/` by `samples/web/pages/404.html`.

## Run it locally

```bash
./gradlew :samples:web:wasmJsBrowserDevelopmentRun
```

Build the production bundle with `./gradlew :samples:web:wasmJsBrowserDistribution`; it lands in
`samples/web/build/dist/wasmJs/productionExecutable`.

Requires a browser with WebAssembly GC (Chrome and Edge 119+, Firefox 120+, Safari 18.2+).

## Features

- **Share a link:** the URL hash follows what you see, for example `#components/Chips/Tag`, `#extensions` or `#dates`.
- **Search:** press `/` to focus the search box, arrows and Enter to pick a result, Esc to close. Spanish keywords work too.
- **Copy:** every code block has a Copy button; each demo has View source and Copy link.
- **Light and dark** themes, and a layout that adapts to phones.

## Adding a demo

Add a `Demo(family, name, tag, description, code) { preview }` entry to `demos` in `Components.kt`, and its source file to
`sourceFiles` so *View source* points at the right place. Extensions and dates live in `Extensions.kt` and `Dates.kt`.

## Coverage

`catalogCoverage` compares the library's public API with what the catalog shows, so the catalog cannot silently fall behind:

```bash
./gradlew :samples:web:catalogCoverage
```

It scans the public `@Composable` functions and extension functions of `jchucomponents-ui` and `jchucomponents-foundation`
and looks for each name in `samples/web/src`. The report is written to `samples/web/build/reports/catalog-coverage.md`.

- `coverage-baseline.txt` lists the known gaps. The task fails only for **new** public API without a demo, and tells you
  when a baseline entry became covered so you can remove it.
- `coverage-ignore.txt` lists names that intentionally have no demo; every line needs a `# reason`.
- After adding demos, regenerate the baseline with `-PupdateBaseline=true`.

A name counts as covered when it appears as a word anywhere in the catalog sources, so a generic name can match by accident.
Treat the percentage as a guide. CI runs this check in the `web-catalog` job.
